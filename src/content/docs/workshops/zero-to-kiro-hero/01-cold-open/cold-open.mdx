You're about to run a feature that looks completely finished. Clean code, a real answer, ships
today. Then we'll ask the one question nobody asked while it was being built: *is it right?*

That gap, between code that **looks** right and code you can **prove** is right, is the whole
workshop.

## Meet the app

Everyone starts from the same app, a tiny budget tracker. **You didn't write it**, and that's
the point. Real work almost never starts from a blank page, and a shared starting point means
nobody in the room is ahead.

<Steps>

1. Start the app you cloned in
   [Setup → Get the Starter App](../../00-setup/the-starter-app/):

   ```bash
   dotnet run --urls http://localhost:5000
   ```

2. It rebuilds its sample data on every start, so everyone sees identical numbers. (If port
   5000 is taken, pick another and adjust the URLs below.)

</Steps>

## The feature that looks done

The app answers a simple question: *how much did I spend this month?* Ask it:

```bash
curl "http://localhost:5000/summary"
```

```json
{ "month": "…", "totalSpent": "$1,300.00", "totalSpentCents": 130000 }
```

**$1,300.00.** Clean JSON, a confident number, formatted correctly. It looks done. It's exactly
the kind of plausible, agent-generated code that gets shipped every day.

<Aside type="tip" title="Instructor option: build it live">
For the full effect, ask the agent to build this from scratch instead of running the shipped
endpoint: *"Add an endpoint that returns how much I spent this month."* It produces clean,
working code in seconds, and the same wrong answer. The sample data is rigged so any
straightforward implementation lands here.
</Aside>

## The one question

Is **$1,300** right? Nobody in the room knows yet, and neither did the code. Look at what it
counted:

```bash
curl "http://localhost:5000/transactions"
```

Three things are hiding in that list:

- A **$200 "Transfer to savings."** You didn't *spend* that. You moved it to your own account.
  (There's a matching `+$200` in Savings, so it also inflates your income.)
- A **$100 grocery refund.** Money came *back*. It should *reduce* spending, not be ignored.
- A **$150 "Pending groceries"** charge that **hasn't cleared yet.**

None of those were wrong on purpose. The code did the obvious thing. It summed everything that
looks like money going out, because **nobody told it what "spent" means.**

<Aside type="caution" title="Hold that number">
We're not going to fix it yet. Hold onto **$1,300**. In Act 3 you'll come back to this exact
feature, make the number honest, and (here's the part that matters) be able to *prove* the new
one is right.
</Aside>

## Why this is the whole workshop

The agent isn't dumb, and it isn't your enemy. It was *fast*, it was *confident*, and it
produced something that looks finished. It just guessed at decisions you never gave it. That's
the real shape of working with an agent. It has huge power, zero context, and no guardrails, and
your job is to supply both.

That's the next ninety minutes:

- **Act 1 · Context.** Give the agent the knowledge it's missing (your conventions, your
  definition of "spent").
- **Act 2 · Control.** Put guardrails on what it's allowed to do.
- **Act 3 · Brownfield.** Return to this feature and make it correct, on purpose, with a way
  to prove it.

<Aside type="note" title="Checkpoint">
Everyone has the app running and has seen `/summary` return **$1,300**, and can name at least
one reason that number is wrong (the transfer, the refund, or the pending charge).
</Aside>
