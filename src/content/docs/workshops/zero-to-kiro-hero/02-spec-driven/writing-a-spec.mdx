import { Tabs, TabItem, Steps, Aside, FileTree } from '@astrojs/starlight/components';

A spec is how you tell Kiro *what* to build before it writes any code.

<Steps>

1. Create the spec file in your project root.

   <Tabs syncKey="os">
     <TabItem label="macOS / Linux">
       ```bash
       touch .kiro/specs/checkout.md
       ```
     </TabItem>
     <TabItem label="Windows (PowerShell)">
       ```powershell
       New-Item .kiro/specs/checkout.md
       ```
     </TabItem>
   </Tabs>

2. Describe the feature in plain language, including acceptance criteria.

3. Run the agent against the spec.

</Steps>

<Aside type="tip" title="Expected output">
You should see Kiro propose a file tree before generating. If it doesn't, your spec is
probably too vague — add concrete acceptance criteria.
</Aside>

<Aside type="caution">
The agent will overwrite existing files in scope. Commit first.
</Aside>
